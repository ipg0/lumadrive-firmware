# Firmware updates

Flash firmware containing the mesh OTA receiver over USB on every node first. Connect the app to the controller, select **Update firmware**, and choose the ESP32 application `firmware.bin` (not a merged flash or hardware configuration image). The app uploads the image to each paired node in sequence, then updates the controller. Each device writes its inactive OTA slot, checks the CRC and ESP-IDF image validity, selects the slot, and restarts. A node failure stops the sequence before the controller is updated; retry when the node is available. The existing NVS and hardware configuration partitions are not rewritten.

The mesh currently uses unencrypted ESP-NOW peers. Matching the paired controller MAC does not cryptographically authenticate OTA frames: an attacker able to spoof that address can inject firmware. Secure boot is not enabled by the current configuration. Do not deploy mesh OTA where this exposure is unacceptable; authenticated peer provisioning or signed firmware verification is needed to remove it.

The current build does not enable ESP-IDF rollback. Image validation detects malformed firmware but cannot guarantee that a valid image will start successfully; USB recovery remains necessary if it does not boot. Changes to the partition table, including the hardware partition rename, require a USB firmware flash.

The encrypted BLE characteristics `294b8b31-57d2-bf85-dc41-5c612c9d1539` (write) and `294b8b32-57d2-bf85-dc41-5c612c9d1539` (read) use little-endian fixed-width values. Every command starts with a one-byte operation and a four-byte nonzero transfer ID. Begin (1) adds a four-byte image length and IEEE CRC32; chunk (2) adds a four-byte offset and data; validate (3), abort (4), select boot partition (5), and restart (6) have no additional fields. Send one operation at a time and poll status for acknowledgement. Each frame must fit the negotiated ATT MTU minus three bytes and the 512-byte characteristic limit.

For a node update, append its six-byte MAC address to Begin and limit each chunk's data to 200 bytes. The controller forwards the commands using stop-and-wait ESP-NOW frames, with transfer-specific acknowledgments and duplicate suppression. BLE status reflects the selected node. Error 9 denotes an unpaired target, and error 10 denotes a mesh transfer timeout.

Status is 16 bytes: stage, error, two reserved bytes, transfer ID, accepted offset, and total length. Stages are idle (0), receiving (1), validated (2), failed (3), selected (4), and node restart requested (5). A disconnected or inactive upload is aborted; selection occurs only after the full length, CRC, and ESP-IDF image validation succeed. A selected image must be rebooted before starting another upload.
